# Symlink map

This document lists the local paths managed by `scripts/install.sh` and `scripts/uninstall.sh`.

## Shared paths

| Source | Target | Type |
|---|---|---|
| `skills/` | `~/.agents/skills` | Symlink |

## Claude Code

| Source | Target | Type |
|---|---|---|
| `instructions/AGENTS.md` | `~/.claude/AGENTS.md` | Symlink |
| `instructions/CLAUDE.md` | `~/.claude/CLAUDE.md` | Compatibility symlink |
| `skills/` | `~/.claude/skills` | Symlink |
| `agents/claude/` | `~/.claude/agents` | Symlink |
| `commands/claude/` | `~/.claude/commands` | Symlink |

## opencode

| Source | Target | Type |
|---|---|---|
| Generated by `scripts/install.sh` | `~/.config/opencode/opencode.jsonc` | Generated file |
| `agents/opencode/` | `~/.config/opencode/agent` | Symlink |
| `commands/opencode/` | `~/.config/opencode/command` | Symlink |

The opencode config is generated instead of symlinked because it must point to the absolute `instructions/AGENTS.md` path for the current clone.

The generated config also sets `skills.paths` to the current clone's absolute `skills/` path.

## Antigravity CLI

| Source | Target | Type |
|---|---|---|
| `instructions/AGENTS.md` | `~/.gemini/config/AGENTS.md` | Symlink |
| `skills/` | `~/.gemini/config/skills` | Symlink |
| `agents/antigravity/` | `~/.gemini/config/agents` | Symlink |

The Antigravity global config root is `~/.gemini/config/`. Agent files live as `agents/antigravity/<name>/agent.md`, which map 1:1 to the `<name>/agent.md` layout Antigravity's agent scanner expects under `~/.gemini/config/agents/`.

## Backup behavior

When a target already exists, `install.sh` moves it to a backup path before creating the managed path.

Backup format:

```text
<target>.backup-<timestamp>
```

`uninstall.sh` does not restore backups automatically.

## Codex CLI

| Source | Target | Type |
|---|---|---|
| `instructions/AGENTS.md` | `~/.codex/AGENTS.md` | Symlink |
| `agents/codex/` | `~/.codex/agents` | Symlink |
| `skills/` | `~/.agents/skills` | Symlink |
| `adapters/codex/skills/<command>/` | `~/.codex/skills/<command>` | Per-skill symlinks |

Codex discovers shared user skills from `~/.agents/skills`; that link is installed once and serves Codex alongside the other supported harnesses. Codex workflow command equivalents are skills named after the canonical commands, invoked with `$<command>`; they live in `adapters/codex/skills/` and are linked per skill into `~/.codex/skills` so they never appear in another harness's skill list. The per-skill links also leave the Codex-managed `.system` skills and any curated installs in `~/.codex/skills` untouched. The installer does not manage `~/.codex/config.toml`, auth, sessions, or cache.
